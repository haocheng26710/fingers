## Reproduction and root causes

The independent mismatch report was reproduced against the unchanged production implementation in a self-cleaning temporary directory:

```text
MISMATCH_ACCEPTED metadata=-18.0 config=-20.0
```

The first regression run produced `6 failed, 3 passed`. It confirmed that both public persistence APIs exposed a `spec` parameter, a call without it failed, positive durations rounding to zero and one sample were accepted, `-10000 dBFS` was accepted, and generation leaked `ZeroDivisionError` at `actual_peak / rms`.

The causes were independent and direct:

1. Persistence compared metadata only with the caller-supplied spec, never with `spec_from_audio_config(loaded.model)`, so a legitimate config hash could be paired with another legitimate spec and waveform.
2. `sweep_duration_s > 0` did not imply a usable rounded sample count.
3. `digital_peak_dbfs <= 0` did not imply a positive float32 amplitude, and generation did not check quantized peak/RMS before division.

## API and numeric corrections

The public APIs are now:

```text
publish_offline_ess_artifact(development_root, artifact_id, loaded)
validate_offline_ess_artifact(artifact_root, loaded)
```

They verify `loaded.kind == "audio"`, require `AudioConfig`, derive the sole specification internally, and use that derived value for generation, metadata, and deterministic validation. Only the private staging validator accepts the already-derived spec. The CLI loads config and passes only `LoadedConfig`; there are no peak/duration options, defaults, environment overrides, or second fact source.

The fixed mismatch proof is:

```text
MISMATCH_REJECTED_BEFORE_WRITE {
  development_root: false,
  artifact: false,
  staging: [],
  lock: false
}
```

Metadata whose spec is changed to -18 dBFS and whose sidecar is recomputed is rejected with `ESS specification does not match the loaded audio configuration`. WAV regeneration, raw hash, config reference, original config hash, and normalized config hash all remain tied to the same loaded configuration.

`EssSignalSpec` now requires its half-up rounded sweep count to be at least two. The reproduced post-fix signals are `ZERO_SAMPLE_SPEC_REJECTED 0` and `ONE_SAMPLE_SPEC_REJECTED 1`; a duration rounding to exactly two samples remains valid.

The dBFS validator computes `10 ** (dbfs/20)` and requires both the float64 result and its actual NumPy float32 conversion to be finite and positive. Thus no arbitrary fixed dBFS floor is introduced. `-10000 dBFS` produces `UNREPRESENTABLE_FLOAT32_PEAK_REJECTED`; the smallest positive float32 target remains valid and generates positive peak/RMS, while mathematical 0 dBFS remains expressible without changing `playback_authorized=false`.

`generate_ess` independently defends target amplitude, normalization factor, quantized sweep peak, output peak, RMS, and crest factor. All must be finite and positive. Defensive tests verify zero-energy and zero-RMS paths raise `EssError`; `ZeroDivisionError` no longer escapes.
